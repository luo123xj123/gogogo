## 一、技术选型

### 1.1 选型决策

| 方案 | 技术栈 | 优势 | 劣势 | 决策 |
|------|--------|------|------|------|
| 方案A | 纯 HTML+CSS+JS 单文件 | 零依赖、即开即用、无需编译 | 可维护性稍弱 | ✅ **V1.0 采用** |
| 方案B | Vite + Vue3 | 工程化、可维护性高 | 需要 Node.js 环境 | 🔜 V1.1 迁移 |
| 方案C | React + TypeScript | 类型安全 | 依赖复杂 | 🔜 长期目标 |

**V1.0 选型理由**：
1. 当前环境无 Node.js，纯 HTML 方案零门槛运行
2. 用户（9-12岁儿童）通过浏览器使用，无需安装
3. 核心围棋逻辑用原生 JS 实现，准确性更高（无框架副作用）
4. 单文件便于调试和问题定位

### 1.2 核心模块划分

```
围棋复盘系统 V1.0.0
├── SGFParser       — SGF 格式解析器（完整支持 FF[4]）
├── GoEngine        — 围棋规则引擎（提子/气/Ko/合法性判断）
├── GameTree        — 棋谱树结构（主线+分支管理）
├── AIAnalyzer      — AI 分析模块（V1.0 规则模拟，后续对接 KataGo）
├── BoardRenderer   — 棋盘渲染（Canvas 2D，HiDPI 适配）
├── WinrateChart    — 胜率曲线（SVG）
├── StorageManager  — 本地存储管理（localStorage）
└── UI              — 页面渲染与交互（首页/复盘/报告/设置）
```

## 二、SGF 解析规范

### 2.1 支持的 SGF 属性

| 属性 | 含义 | 优先级 |
|------|------|--------|
| GM[1] | 棋类（围棋） | P0 |
| FF[4] | SGF 格式版本 | P0 |
| SZ[19] | 棋盘大小（9/13/19） | P0 |
| PB/PW | 黑/白棋手名 | P0 |
| BR/WR | 段位/级位 | P0 |
| DT | 对局日期 | P0 |
| RE | 结果 | P0 |
| KM | 贴目 | P0 |
| HA | 让子数 | P0 |
| B/W | 落子坐标 | P0 |
| AB/AW | 预置黑/白子 | P0 |
| C | 注释 | P1 |
| LB | 标签标记 | P1 |
| TR/CR/SQ/MA | 图形标记 | P1 |

### 2.2 坐标系统

SGF 使用字母坐标（a-s 对应 0-18）：
```
SGF坐标 'a' → 棋盘列/行索引 0
SGF坐标 's' → 棋盘列/行索引 18
```

特殊情况：
- `B[]` 或 `W[]` → 虚手（pass）
- `B[tt]` → 某些旧版 SGF 的虚手写法

### 2.3 分支结构

```
(;GM[1]...             — 根节点（游戏信息）
  ;B[pd]               — 主分支第1手
  ;W[dp]               — 主分支第2手
  (;B[qp]              — 变化图1开始
    ;W[dd])            — 变化图1第2手
  (;B[cd]              — 变化图2开始
    ;W[pp])            — 变化图2第2手
  ;B[fc])              — 主分支继续
```

## 三、围棋规则引擎规范

### 3.1 数据结构

```javascript
// 棋盘状态
board[y][x] = 0 | 1 | 2  // 0=空, 1=黑, 2=白

// 棋子颜色
const BLACK = 1;
const WHITE = 2;
const EMPTY = 0;

// 着法
move = { x: number, y: number, color: 1|2, isPass: boolean }
```

### 3.2 核心算法

**气的计算（BFS）**：
```
findGroup(x, y) → { stones: Set, liberties: Set }
从(x,y)出发，BFS遍历同色连通块，统计气数
```

**提子逻辑**：
```
applyMove(board, move) →
1. 放置棋子
2. 检查对方所有邻接棋子的气
3. 若对方棋子气=0，提取对方棋子
4. 检查自身气（自杀手检测）
5. Ko 检测（与上一局面比较）
返回: { newBoard, captured, isLegal, isKo }
```

**合法性判断**：
- 不能下在有棋子的位置
- 不能自杀（除非能提子）
- 不能造成 Ko（劫）

### 3.3 局面哈希（Ko检测）

使用 Zobrist Hash 快速比较局面是否重复：
```javascript
hash = XOR(hash_table[color][x][y]) for all stones on board
```

## 四、AI 分析模块规范

### 4.1 V1.0 规则模拟算法

由于 KataGo 未部署，V1.0 使用以下规则模拟胜率：

```
winrate = base(50%) 
  + positionScore()    // 基于位置权重的形势评估
  + captureScore()     // 基于提子数的优势评估  
  + territoryHeuristic() // 基于区域控制的领地估算
  + momentum()         // 连续着手质量的惯性
```

**位置权重矩阵（19路）**：
- 星位（4-4）：高权重
- 天元（10-10）：中权重
- 边路：低权重
- 角部：中权重

### 4.2 问题手识别规则

```
问题手判定：
1. 胜率变化 < -10% → 严重问题手（红色标记）
2. 胜率变化 < -5%  → 一般问题手（橙色标记）
3. 胜率变化 > +5%  → 好手（绿色标记）
4. 胜率变化 > +15% → 极佳手（金色标记）
```

## 五、胜率曲线渲染规范

### 5.1 SVG 实现方案

```
坐标系：
- X 轴：手数（0 到 totalMoves）
- Y 轴：黑方胜率（0% 到 100%）
- 50% 线：中线参考线

关键节点标记：
- 红色圆点：胜率下降 >10% 的问题手
- 绿色圆点：胜率上升 >10% 的好手
- 紫色圆点：关键转折点（胜率波动 >15%）

当前手数指示线：
- 垂直虚线 + 移动圆点
```

### 5.2 交互规范

- 点击曲线上的点 → 棋盘跳转到对应手数
- Hover 显示该手胜率详情
- 拖动当前指示线 → 实时更新棋盘
